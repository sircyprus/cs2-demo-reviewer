# Architecture

## Overview

```
 demos/*.dem(.zst|.bz2|.gz|.zip)                       visitor's browser
        │                                                    │ drop a file
        ▼                                                    ▼
  review.js  (Node, native parser)              worker.js (Web Worker, WASM parser)
        │                                                    │
        └──────────── site/src/parser/analyse.js ────────────┘
                       (one shared analysis module)
        │                                                    │
        ▼                                                    ▼
 site/public/data/*.json (local only)        IndexedDB (stays on the device)
                                    │
                                    ▼
                  React app (Matches · Players · Head to Head · Report · Replay)
```

The site is fully static. There is no backend: pre-parsed demos are JSON files served as-is, and demos added by a visitor are parsed in their browser.

## Repository layout

| `site/src/parser/wasm/` | Compiled CS2-capable demoparser2 (WASM) and a README describing how it was built. |
| `site/src/replay/engine.js` | Canvas replay engine (camera, drawing, timeline, playback). |
| `site/src/replay/Viewer.jsx` | React UI around the engine. |
| `site/src/pages/` | `Home` (+ `home/` tabs), `Report`, `Replay`. |
| `site/src/lib/` | `data.js` (fetch + hooks), `store.js` (IndexedDB), `stats.js`, `util.js`. |

## Parsing

Both parsers wrap demoparser2 (Rust). `analyse.js` only needs a small `api`:

```js
api.header()                    // -> { map_name, ... }
api.events(names, playerProps)  // -> flat array of events (event_name, tick, ...)
api.ticks(props, tickList)      // -> rows { tick, steamid, name, ...props }
```

- **Node** binds it to the native parser by file path.
- **Browser** binds it to the WASM build over a `Uint8Array`.

A demo takes three passes: header, one multi-event pass (`player_death`, `player_hurt`, `round_*`, grenade detonations, bomb events, `round_freeze_end`) and one tick pass (positions, health, yaw, team, armour, weapon, money and equipment value at every 8th tick plus the end of each freeze time).

The same demo parsed by the native and the WASM parser gives identical output (verified on the Mirage demo).

`analyse(api, events)` returns the report (rounds, players, scores). `buildReplay(api, analysis, events)` returns replay frames. `summarise` builds the compact entry used by the index page. SteamIDs are replaced by a 12-character `cyrb53` hash (`anon`) before anything is written.

### Browser pipeline (`worker.js`)

1. Decompress: `.zst` via `fzstd`, `.bz2` via `seek-bzip` (with a `Buffer` polyfill), `.gz` via `DecompressionStream`, `.zip` via `fflate`.
2. Check the `PBDEMS2` magic bytes.
3. Run the shared analysis with the WASM api.
4. Post results back; the page stores `{slug, summary, analysis, replay}` in IndexedDB and terminates the worker.

One worker is used per file and then thrown away, because WebAssembly memory cannot shrink. Slugs for local demos are `local_<name>_<byte-length>`.

### The WASM build

The `demoparser2` package on npm (0.15) crashes on CS2 demos, so the WASM is built from the upstream repo (`src/wasm`, MIT) with three patches: `csgoproto/build.rs` made a no-op (generated protobuf code is already committed), `std::time::Instant` replaced by a shim (it panics on wasm), and results serialised as plain objects with a panic hook. Details and tool versions are in `site/src/parser/wasm/README.md`. To update the parser, re-fetch upstream, re-apply the patches, run `wasm-pack build --release --target web` and replace the three files.

## Data files

Everything under `site/public/data/`:

| File | Contents |
| --- | --- |
| `index.json` | `{ demos: [summary…], failed: [{file, err}] }`. Summary = file, slug, map, rounds, score, date, duels (`"attackerId>victimId": [kills, headshots]`), and a short line per player. |
| `<slug>.json` | Full analysis: rounds (winner, reason, kills with tags), players (scoreboard stats, team), `startTick`, `endTicks`, `roundStarts`, date and its source. |
| `<slug>.replay.json` | `frames: [[tick, [[x, y, z, hp, yaw, side, armor, weaponIdx, money] \| null, …]], …]` sampled every 8 ticks; `util` (smokes, fire, flashes, HE with durations); `bomb`; `kills`; `rounds` (start/end/freeze end, winner, `eq` economy per side); `weapons`, `names`, hashed `ids`. |

Radar calibration comes from Valve's overview files (`pos_x`, `pos_y`, `scale`; `lowerBelow` for two-level maps) turned into `maps/maps.json`.

## The React app

- Hash routing (`#/demo/<slug>/replay`) so any static host works and the site can live under a sub-path (`base: './'`).
- `Home` merges pre-built demos with IndexedDB demos, applies the date filter, and passes the visible list to the three tabs.
- The replay engine owns the canvas and animation loop. React gets a plain "HUD snapshot" about every 90 ms and when something changes; drawing, zoom and playback never trigger re-renders.

## Publishing

1. Commit and push to `main`. (`site/public/data/` and `demos/` are git-ignored, so no demo data is ever published.)
2. `pages.yml` runs `npm ci && npm run build` in `site/` and deploys `site/dist`. Repo Settings → Pages → Source must be **GitHub Actions**.

The repo must be public for free GitHub Pages. The site is served from the custom domain https://themasturbatorium.com/ (see the README for the DNS records). The deployed site contains only the app: no demo data, names or SteamIDs. Demos a visitor adds are parsed in their browser and stored only in that browser. (Locally generated data still uses a `cyrb53` hash instead of SteamIDs; that is obfuscation, not strong anonymisation.)
